# 去 AI 味与组会表达规范

科研组会 PPT 的听众是导师和同组同学，最忌讳**公众号标题党、商业咨询套话、公文四字对仗、过度煽情与密密麻麻的文字墙**。

## 1. 语气基准

- **平实、克制、直奔事实**：像自己在白板前跟导师和师兄师姐平视讨论，而不是在推销产品或写公众号推文。
- **结论先行，少修饰语**：优先写“谁在什么平台上测出了什么数字 / 做了什么机制 / 没解决什么问题”。
- **把细节留给嘴说（放进备注栏）**：页面上只留骨架、核心数字和判断；完整背景、论文作者列表、展开解释全部写入 PowerPoint 演讲者备注（Speaker Notes）。

---

## 2. 严格黑名单（出现即改写）

| 类别 | 禁用表达（AI 味 / 公众号体） | 改为（平实组会表达） |
|---|---|---|
| **夸张比喻与热词** | 容量杀手、静默悬崖、致命死穴、暗藏拷贝坑、互相打架、最凶的时刻、突刺、打破了…假设 | 内存压力表现、页压缩变慢 2.5×、关键局限、共享开销、互相干扰、内存和带宽峰值 |
| **互联网/公文动词** | 精准卡位、定锚、怎么打、抢占先机、赋能、抓手、闭环、沉淀、底层演进、五项可复用积木 | 课题位置、本次调研、实测计划、时间窗口变窄、可借用的方法 |
| **反问句式小标题** | 为什么解码如此脆弱？为什么静默悬崖比 OOM 更致命？Phase 0 怎么打？ | 解码对带宽敏感、容量不足的表现、Phase 0 实测计划 |
| **情绪标点与装饰符** | 任意感叹号 `！`、满屏 `★` / `⚠️` / `🚀`、单句塞满 `①②③④⑤` | 句号或无标点、简洁编号 `1. 2. 3.` 或分行短句 |
| **自夸与客套语** | 覆盖 30+ 篇顶会工作、一站式全景解读、敬请批评指正、感谢各位观看 | `@作者 · 日期`、`欢迎讨论` 或直接以组会讨论议题收尾 |

## 3. 真实改写对照示例

- **标题**：
  - ❌ `分立显存各走各路，桌面统一内存却把多会话 KV 和同机工具锁进了同一块池子`
  - ✅ `桌面统一内存把多会话 KV 和本地工具放进了同一块物理内存`
- **批注框**：
  - ❌ `死穴：灰色 "Tool Stall"！换成真实本地编译，这里恰恰是内存和带宽最凶的时刻！`
  - ✅ `关键局限：灰色 "Tool Stall" —— 论文用 1–100 秒休眠模拟工具调用，期间假设 0 MB 内存、0 GB/s 带宽；换成真实编译、单测或容器，这里会出现明显的内存和带宽峰值。`
- **行动建议**：
  - ❌ `NEXT · 抢占时间窗口：立刻推进 Phase 0，抢先占位！`
  - ✅ `NEXT：完成 Phase 0 刻画（DGX Spark 真实负载实测，考虑先投 Workshop 占位）`

## 4. 排版与字数自查清单

1. **无孤字换行（Widow）**：如果某条要点最后一行只掉出 1–2 个字（如“同。”“留。”“应用”），精炼措辞删去 2–3 个冗余字，让它收进上一行。
2. **严禁省略号截断**：不要为了凑长度在句尾加 `...` / `…` / `等等`，应直接压缩表达。
3. **同页信息分层**：有原论文图/表的页面，旁边文字控制在 **3 条以内**，每条不超过 2 行，避免文字跟图片抢视觉焦点。
4. **演讲者备注必写**：每页在 `notes_slide` 中附上 ~100–250 字自然口播提纲，方便汇报时直接参考。
